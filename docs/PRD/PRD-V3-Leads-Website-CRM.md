# PRD：NepTune V3 — 线索收录网站与轻量 CRM

本文档描述 V3 新增的**线索展示网站**与**类 CRM 能力**：在现有抓取 + Telegram 推送的基础上，提供 Web 端登录、每日更新线索的浏览与管理，便于团队集中查看、筛选与跟进。

**仅规划与需求，不涉及具体实现代码。**

---

## 一、与 v1/v2 的关系

| 层级 | v1 | v2 | V3 |
|------|----|----|-----|
| 数据来源 | 抓取 → SQLite | 同 v1 + 摘要 | **同 v2**：网站只读同一套数据（如 `leads` 表 + 可选扩展） |
| 推送 | Telegram 卡片 | 卡片含核心描述 | 不变；网站**不替代** Telegram，二者并存 |
| 用户触点 | 仅 Telegram | 仅 Telegram | **Telegram + Web 网站** |

V3 不改变现有爬虫、摘要、推送逻辑；网站作为**新增展示与跟进入口**，数据与「Telegram 里的那条线索」一一对应（同一条 lead：既在群里看到，也能在网站里看到、点开、加备注等）。

---

## 二、产品目标与用户

- **目标**：为每日更新的招聘线索提供一处**可登录的 Web 收录站**，支持列表浏览、筛选、搜索、详情查看与简单跟进（状态/备注），形成轻量 CRM 体验。
- **用户**：运营/招聘侧（与 v1/v2 一致）；使用场景为：在电脑上打开网站 → 登录 → 查看今日/历史线索、按条件筛选、点进详情、记录跟进状态或备注，必要时跳转 Upwork 原链接投递。

---

## 三、功能范围总览

| 模块 | 功能概要 |
|------|----------|
| **登录** | 账号密码登录；默认账号 `Sylicora`，默认密码 `JustGetItDone`；未登录仅可访问登录页。 |
| **线索列表** | 表格或卡片列表展示所有线索；字段与 Telegram 卡片对齐（发布时间、预算、标题、核心描述、直达链接等）；支持分页或懒加载。 |
| **筛选与搜索** | 按平台、抓取日期/发布时间、预算区间等筛选；按标题或核心描述关键词搜索。 |
| **线索详情** | 单条线索详情页：完整描述、核心描述、预算、发布时间、发布方、直达链接等；可在此页记录「状态」与「备注」。 |
| **数据与更新** | 数据来自现有 SQLite（或后续统一数据源）；「每日更新」由现有定时抓取任务保证，网站只读、不负责抓取。 |

## 四、登录系统

### 4.1 需求

- **登录方式**：账号 + 密码，表单提交后服务端校验；通过则建立会话（如 Session/Cookie 或 JWT），后续请求携带会话直至登出或过期。
- **默认账号**：
  - 账号：`Sylicora`
  - 密码：`JustGetItDone`
- **访问控制**：
  - 未登录用户只能访问登录页（及必要的静态资源）；访问列表、详情等需登录，否则重定向到登录页。
  - 登录后可在站点内访问所有已规划页面，并支持「登出」清除会话。

### 4.2 可选扩展（非首版必做）

- 多账号、角色（如只读/编辑）、修改密码、记住我等，可在后续迭代中补充。

## 五、CRM 功能设计（与「Telegram 信息」对齐）

当前「用户线索」即**推送到 Telegram 的那条消息所对应的数据**，字段与 v1/v2 一致，包括但不限于：

- **平台**：如 Upwork  
- **需求标题**：title  
- **核心描述**：core_summary（100 字内中文摘要）或描述前 30 字  
- **预算信号**：budget_signal / salary_raw  
- **发布时间**：published_at（展示为「X 小时前」「昨天」等）  
- **直达链接**：source_url（跳转 Upwork 职位页）  
- **发布方**：publisher  
- **完整描述**：description（详情页展示）  
- **抓取时间**：crawled_at（用于「每日更新」维度）  
- **扩展信息**：extra（如 work_location、时薪/固定价等）

以下按「列表 → 筛选/搜索 → 详情 → 跟进」的 CRM 动线设计。

### 5.1 线索列表（列表视图）

- **展示内容**：每条线索以一行（表格式）或一张卡片展示，至少包含：
  - 发布时间（或抓取时间，可配置展示其一）
  - 预算信号
  - 需求标题
  - 核心描述（截断展示，如 50 字 +「…」）
  - 直达链接（可点击跳转）
  - 平台标签
- **排序**：默认按发布时间或抓取时间倒序（新的在前）；可选按预算、标题等排序。
- **分页 / 懒加载**：数据量较大时支持分页或滚动加载，避免一次拉取过多。

### 5.2 筛选与搜索

- **筛选**：
  - 平台：如 Upwork（后续可扩展 Backstage、LinkedIn）
  - 时间范围：按抓取日期（crawled_at）或发布时间（published_at）筛选「今日」「近 7 日」「近 30 日」或自定义区间
  - 预算：可选「仅有时薪」「仅有固定价」「两者皆有」或按区间（若数据支持）
- **搜索**：对「需求标题」「核心描述」做关键词搜索（支持单关键词即可；多词、高亮等可后续增强）。

### 5.3 线索详情页

- **展示**：单条线索的完整信息，与 Telegram 卡片一致并补充完整描述：
  - 需求标题、平台、发布方
  - 发布时间、抓取时间
  - 预算信号
  - 核心描述
  - 完整描述（长文本，可折叠或分块展示）
  - 直达链接（明显按钮或链接）
  - 扩展信息（若有）：工作地点、时薪/固定价等
- **跟进区（CRM 核心）**：
  - **状态**：如「未跟进」「已读」「有意向」「已投递」「已忽略」等可选项；每条线索仅有一个当前状态，可修改并保存。
  - **备注**：自由文本，支持多条或单条可编辑；可带时间戳（谁在何时添加，若有多用户可后续扩展）。
- **操作**：保存状态与备注；「在 Upwork 打开」跳转 source_url。

### 5.4 数据来源与「每日更新」

- **数据来源**：与现有爬虫一致，读取同一套存储（如 SQLite `leads` 表）；若当前表结构未包含 `core_summary`，可在 V3 中扩展表结构或从 `extra_json` 中解析，保证列表/详情与 Telegram 展示一致。
- **每日更新**：不单独为网站做抓取；依赖现有定时任务（如 `run_scheduler`）每日抓取并入库，网站只读最新数据即可，打开列表即能看到「今日新增」与历史线索。

### 5.5 与 Telegram 的对应关系

| Telegram 卡片项 | 网站对应 |
|-----------------|----------|
| 🕐 发布时间 | 列表/详情的「发布时间」 |
| 💰 预算信号 | 列表/详情的「预算」 |
| 📝 需求标题 | 列表/详情的「标题」 |
| 🔍 核心描述 | 列表/详情的「核心描述」 |
| 🔗 直达链接 | 列表/详情的「直达链接」 |
| （无） | 详情页「完整描述」「状态」「备注」 |

## 六、非功能需求（建议）

- **性能**：列表首屏加载时间可接受（如 &lt; 3s）；详情页即时打开。
- **安全**：密码不以明文存储；传输建议 HTTPS；会话有过期时间。
- **兼容**：支持常见浏览器（Chrome、Safari、Edge 等）；可优先桌面端，移动端兼容为加分项。

---

## 七、非目标（V3 首版不包含）

- 不替代 Telegram 推送；不改变现有抓取、摘要、推送逻辑。
- 不做多用户/权限管理（首版可单账号）、不做邮件/站内通知、不做复杂报表与统计图表（可后续迭代）。
- 不做线索的「编辑/删除」数据源字段（仅允许编辑状态与备注等跟进信息）。

## 九、总结

V3 在 v1/v2 基础上增加**线索收录网站**与**轻量 CRM**：

1. **网站**：收录每日更新的线索，与 Telegram 同源数据，支持登录（默认账号 `Sylicora`，密码 `JustGetItDone`）。
2. **CRM 能力**：列表（与 Telegram 信息对齐）、筛选与搜索、线索详情（含完整描述）、状态与备注的跟进，直达链接跳转 Upwork；数据每日随现有抓取任务更新，网站只读不写抓取逻辑。
3. **首版范围**：登录 + 列表 + 筛选/搜索 + 详情 + 状态/备注；多用户、权限、报表等留待后续迭代。

本文档仅作 PRD，不包含具体技术实现与代码。
